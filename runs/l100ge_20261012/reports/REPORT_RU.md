# FlyGraph L100GE — дообучение генеративной 100M через низкоранговую выходную коррекцию

**Дата:** 12 октября 2026. **Статус:** завершено обучение и фиксированная оценка, гипотеза **НЕ ПОДТВЕРЖДЕНА**. **Цель превзойти Qwen3.5‑0.8B не достигнута.**

## Зачем проводился эксперимент

Ранние эксперименты L100A/L100K показали, что формально корректные `F=<число>` не означают, что генеративный языковой backbone правильно выбирает данные или решает задачи. Отдельный L100K продемонстрировал узкую обучаемую адресную память на специально заданном ASCII-формате, но не улучшение обычной открытой генерации. L100GE проверяет, может ли малое обучаемое дополнение к реальному 100M backbone исправить качество генерации на смешанных задачах.

## Модель и воспроизводимость

- **База:** FlyGraph L100EC curriculum; реальный проверенный checkpoint 100,028,328 параметров, BF16, SHA256 `07e33eb2c6aab5727fbb72c0b403bc83ca8e5695d379106af089b27baf995b25`. Полностью заморожен. Уже опубликован в `models/l100ec_curriculum_bf16_07e33eb2/` в GitHub побайтовыми частями.
- **Дообучение:** LoRA-подобная коррекция финального RMSNorm hidden state перед tied vocabulary projection: `x → x + W_up(W_down(x))`, размеры 768→8→768, **12 288 обучаемых параметров**. Всего 100 040 616 параметров; 100 028 328 заморожены. Это не full fine-tune, не новая модель с нуля.
- **Путь инференса:** исходный autoregressive `base.generate` для полного словаря из 8192 токенов, greedy, EOS. Коррекция реализована через PyTorch forward hook `base.norm`; ответ не проходит через арифметический решатель, regex-key parser, список кандидатов или Qwen.
- **Инициализация:** up matrix = 0, down ~ Normal(0,.02); seed 121220, sampler 121221; AdamW lr 0.001, betas (0.9,0.95), decay 0, clip norm 1.
- **Процедура:** 256 полных optimizer updates, в каждом 2 memory + 2 replay примера, микробатчи 2, взвешивание градиента по числу целевых токенов. CPU, torch autocast BF16 и наследуемый FP32 delta operator; CUDA и RTX3090 недоступны.
- **Корпус:** неизменяемые локальные синтетические L100A train_memory/train_replay, включая RU/EN текст, память, расчёты, алгоритмы и Python. Точные файлы и SHA включены в релиз; полное отделение от исторического предобучения L100EC подтвердить невозможно.
- **Checkpoint:** native FP32 `adapter.safetensors`, `training_state.pt` с оптимизатором/RNG/sampler на шагах **64/128/192/256**, а также их SHA и статус. Веса 100M base не перезаписаны, родительский optimizer неизвестен и не симулируется.
- Регистрация и критерий зафиксированы в GitHub **до обучения**, `runs/l100ge_20261012/REGISTRATION.md`. Окончательная точка 256, без выбора по held.

Тренировочная loss уверенно снижается; этого недостаточно для вывода о качестве на held данных. Все 256 шагов сохранены в `metrics/TRAIN_LOG.json`.

## Held-out оценка без подгонки

Фиксированные заранее первые 60 задач `regression.jsonl` и первые 100 `iid.jsonl`, всего **160**. Проверена непересекаемость канонических групп с двумя обучающими наборами. На каждой задаче генерация полного словаря с ограничением 24 новых токена, необходимы EOS и строгий `F=<целое>`. Полные сырые 320 результатов находятся в `metrics/PREDICTIONS.jsonl`.

| Метрика | Неизменённая L100EC | L100EC + обученная LoRA |
|---|---:|---:|
| Strict correct /160 | **3** (1.875%) | **1** (0.625%) |
| EOS | 160/160 | 160/160 |
| Формат `F=<число>` | 160/160 | 160/160 |
| Арифметика /15 | 0 | 0 |
| Условия /15 | 0 | 0 |
| Трассировка кода /10 | 0 | 0 |
| Списки /10 | 2 | 0 |
| Обновления памяти /110 | 1 | 1 |

**Изменение −1.25 процентного пункта. Заранее зарегистрированный критерий +3п.п. не выполнен.** Формат ответа корректен, но семантическая правильность почти отсутствует. Дополнительный проверочный запрос `What is 2 + 3? Answer:` дал неверный текст `2\n    x *= 2\n    ` без EOS за 8 токенов, подтверждая, что модель не стала надёжным вычислителем.

## Инженерные проверки

- 4 теста на точные свойства mask/shift и количество параметров, загрузку реально сохранённых весов, генерацию исходной и адаптированной моделей и **детерминированное повторение следующего optimizer step** из полного native checkpoint; все пройдены (`4 passed`).
- Четыре checkpoint manifest проверены по SHA256 для весов и training state.
- Датасеты, tokenizer, исходники *точно исполнявшейся* версии и более переносимый путь запуска архивируются отдельно от чекпоинтов.
- Большие 100M родительские BF16-веса публиковались ранее как обычные Git объекты и собираются при запуске. Релиз L100GE не подменяет их одними SHA и не дублирует 200МБ в новом source-архиве.

## Ограничения и решение

Это **отрицательный завершённый эксперимент**, не доказательство общей невозможности LoRA. Только один seed, синтетические задачи, небольшой корпус, специфичная архитектура с исходным очень слабым pretraining и один вид LoRA. Не проведены независимые EvalPlus, RU/EN language benchmark или новый парный прогон Qwen3.5-0.8B; нельзя заявлять паритет с Qwen или улучшение универсального интеллекта.

**Практический вывод:** замороженный слабый backbone + 12К-параметрический выходной адаптер учит тренировочные ответы, но не обучает новое рассуждение. Следующий эксперимент должен изменять внутренние представления всего backbone или его существенные блоки, использовать независимые задания разных типов и достаточный разнообразный корпус, затем сравнивать с корректно законченным Qwen baseline на тех же задачах.
